Dossier de sortie des APK de QuelTemps.

Fabrication :

    npm run apk

Le script (scripts/apk.mjs) resynchronise public/ vers les assets Android,
compile, puis depose le resultat ici sous le nom queltemps-buildN.apk, N etant
le numero suivant celui deja present. Gradle, lui, ecrit toujours au meme
endroit (android/app/build/outputs/apk/debug/app-debug.apk) et ecrase donc la
compilation precedente : c'est ce dossier qui garde l'historique.

Les .apk ne sont PAS suivis par git (~6 Mo chacun, non compressibles d'une
version a l'autre). Ce fichier l'est, pour que le dossier existe sur une
copie fraiche du depot.

Ce sont des builds DEBUG, signes avec la cle de debogage : bons pour un essai
sur telephone, jamais pour le Play Store.

Pour le Play Store (02/08/2026) :

    npm run apk -- --release

produit queltemps-releaseN.aab, un Android App Bundle. C'est le seul format
que Google accepte depuis 2021 ; il ne s'installe PAS sur un telephone, la
decoupe en APK etant faite par Google. Il n'est signe que si
android/keystore.properties existe (voir android/keystore.properties.exemple),
et le script le dit en clair sinon.

A SAVOIR sur queltemps-release1.aab, s'il traine encore ici : c'est une
compilation de VERIFICATION DE CHAINE, faite pour prouver que bundleRelease
passe avec cet outillage. Elle n'est ni signee, ni a jour (elle precede
l'ajout de la page de confidentialite). Ne pas la televerser : recompiler.

Et INCREMENTER versionCode dans android/app/build.gradle avant CHAQUE envoi,
y compris vers une piste de test. Google refuse un numero deja vu, meme
apres suppression.

Installation sur le Redmi Note 11 : "Installer via USB" n'etant pas active
(compte Mi requis), on passe par un adb push vers /sdcard/Download puis une
installation a la main. Un fichier depose par adb n'est pas indexe, il
n'apparait donc pas dans la vue "Telechargements" du gestionnaire de fichiers.
